Raw data is not training data

Eight cleaning stages run over three real corpora — and most of the corpus does not survive. Three of the nine standard quality rules turn out not to be language-neutral: applied unchanged to Indian-language text they do not filter it, they delete it, while reporting a healthy-looking yield.

Live deduplication, PII masking, and the false positives
 05

Out of what?

A model becomes what it reads, so deciding how much of each kind it reads looks like choosing seven percentages that add to 100 — and anyone can do that. The work is answering “out of what?” for each one. Drag the shares and watch some of them stop being affordable: one lane asks for more than any amount of re-reading could ever be worth.

Four mixtures trained and scored — with the seed noise shown
 06

What did it read on day forty?

Fifty days into a training run something looks wrong, and you want to know which text the model read on day forty. Working it out again from the code that chose the order gives a confident answer about a run that did not happen, as soon as one line of that code changes. Writing it down as it happens does not — and the record can be edited, but not quietly.

A real crash, a resume onto the same batch ids, and an auditor that shares no code with the run
 07

Deleting the output head

A language model keeps one row of numbers per word, and keeps that table twice — once to read words in, once to choose the next one. A published trick deletes the first by computing each row from the word's spelling, then says the second cannot follow and lists it as a limitation. It can follow: the code reads back exactly, the second table ties to the first, and the result is smaller than the design it replaces.

Exact self-certifying inversion, four real words a tied head provably cannot separate, and the one term that fixes it
